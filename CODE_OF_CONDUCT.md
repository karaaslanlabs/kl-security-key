# Code of Conduct

KL Security Key is an experimental open-source security engineering project maintained by Karaaslan Labs. We want technical discussion and collaboration around the project to remain respectful, evidence-led, and safe for contributors and users.

## Expected behavior

When participating in this project, please:

- communicate respectfully and professionally;
- focus criticism on technical claims, code, evidence, and documented behavior rather than individuals;
- assume good faith while remaining precise about security and interoperability claims;
- disclose conflicts, limitations, uncertainty, and relevant testing conditions when they materially affect a contribution;
- protect private or sensitive information, including credentials, PINs, private keys, account data, secret-bearing device images, and non-public security details;
- respect upstream authorship, licensing, provenance, and third-party trademarks;
- help keep discussions useful, reproducible, and within the documented scope of the project.

## Unacceptable behavior

The following is not acceptable in project spaces:

- harassment, intimidation, threats, discriminatory abuse, or targeted personal attacks;
- sustained disruption, trolling, spam, or deliberately derailing technical discussion;
- publishing another person's private information without permission;
- knowingly submitting fabricated evidence, deceptive test results, or misleading certification/vendor claims;
- encouraging identity spoofing, misrepresentation of certification, or concealment of material trust boundaries;
- publishing unpatched vulnerability details, exploit material, credentials, private keys, or other sensitive security information through public issues, discussions, or pull requests when private reporting is appropriate.

## Security reports are handled separately

A security vulnerability is not a Code of Conduct report simply because it concerns security.

**Do not open a public issue, discussion, or pull request for an unpatched vulnerability.** Follow [`SECURITY.md`](SECURITY.md) and report KL-specific security issues privately to `contact@karaaslanlabs.com`.

Use this Code of Conduct for community-behavior concerns. Use the security policy for vulnerability disclosure.

## Scope

This Code of Conduct applies to participation in KL Security Key project spaces, including repository issues, pull requests, reviews, discussions, and other project-managed communication channels.

It also applies when someone is representing the project or Karaaslan Labs in a project-related public interaction.

## Reporting conduct concerns

Report conduct concerns privately to `contact@karaaslanlabs.com`. Include enough context for the maintainers to understand what happened, but do not send unrelated secrets or sensitive device/account material.

Reports will be reviewed on a best-effort basis. Information will be shared only as reasonably necessary to understand the report, protect participants, and take appropriate action.

## Enforcement

Project maintainers may edit or remove comments, commits, issues, pull requests, discussions, or other contributions that violate this Code of Conduct. Depending on severity and pattern of behavior, maintainers may issue a warning, limit participation, temporarily restrict access, or permanently ban a participant from project-managed spaces.

Enforcement decisions should be proportionate, documented when appropriate, and focused on protecting the technical community and the integrity of the project.

## Project boundaries

This Code of Conduct does not change the project's technical or assurance status. KL Security Key remains an experimental engineering/interoperability project and is not represented as FIDO Alliance certified hardware or as a commercial high-assurance security token. See the project [`README.md`](README.md), [`THREAT-MODEL.md`](THREAT-MODEL.md), and [`SECURITY.md`](SECURITY.md) for the applicable technical and security boundaries.
